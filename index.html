Weekly rhythm

Tue1.5 hRead this week's chapter; note anything confusing in LEARNING.md
Thu1.5 hExercises: Rustlings, Exercism, or the phase's drills
Sat4 hProject work
Sun2 hFinish the week's slice, write the log entry, push

About 9 hours a week alongside a full-time job. Change the pace above and every date on this page moves with it.

Ground rules

  1. Write code in every session, reading days included. Aim for 70% writing, 30% reading.
  2. Measure memory in every project from day one: /usr/bin/time -l prints peak resident memory on macOS.
  3. Stuck for 30 minutes? Write the question down, then ask on users.rust-lang.org or ask Claude.
  4. Every project goes on GitHub with a README that states what you measured.
  5. Don't skip the exit checks. If one fails, spend a week on it before moving on.

Hardware kit

Phases 0–4An Apple silicon Mac. It's ARM, so the NEON SIMD you learn carries over to the Pi, and Candle can use its GPU through Metal. Nothing to buy yet.
Phase 5Raspberry Pi 5 (8 GB or 16 GB), an active cooler, and an NVMe drive or a fast microSD card.
Phase 6An ESP32-C6 dev board (RISC-V; Espressif maintains the Rust HAL) or a Raspberry Pi Pico 2 with Embassy. A BMI270 or MPU-6050 IMU breakout, an SG90 micro servo with its own 5 V supply, breadboard, jumpers, LEDs, buttons, and a cheap 8-channel USB logic analyzer.
Later, optionalAn NVIDIA Jetson Orin Nano, if you want CUDA and TensorRT experience.

What “expert” looks like at the end

  • You write unsafe code and can show why it's sound.
  • You choose atomic orderings by reasoning, not by trying SeqCst until it works.
  • You predict memory and latency before measuring, and you're close.
  • You can open a C++ codebase, find the undefined behavior, and bridge it to Rust safely.
  • Your firmware has fixed memory and measured timing.
  • Other people use code you wrote: a crate, or merged pull requests upstream.
