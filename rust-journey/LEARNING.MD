#### Install CMake with Homebrew; you'll need it in Phase 4
JavaScript comparison: `npm` scripts and tools such as Vite or esbuild automate the build process, although they are simpler than CMake.

CMake: It is a free, open-source, and cross-platform meta-build system, which means that it is a build system generator, primarily used for C and C++ projects.

Rather than compiling the source code directly, CMake acts as an orchestrator. It reads a single, tool-independent configuration script, which is called a CMakeLists.txt file, and uses it to generate native build files customised for whatever environment or IDE you are working in.

For instance, users widely agree that CMake's core purpose is to provide a unified build definition, so developers can work across entirely different platforms and IDEs without rewriting the scripts.

Now let's see what the software build pyramid is. To understand CMake, it helps to see where it fits compared to traditional coding tools:

1. The compiler (example: GCC, Clang, MSVC) translates a single source code file into a machine-readable object file.
2. The build system (example: Make, Ninja, etc.) automates the compiler. It looks at a script like a Makefile to determine the exact order to compile hundreds of files and handles tracking which files have changed.
3. The meta-build system, CMake, automates the build system itself. Instead of forcing you to write tedious platform-specific makefiles by hand, CMake writes them for you.

#### VS Code with rust-analyzer, or RustRover; run clippy on save
JavaScript comparison: TypeScript's language server (`tsserver`) provides editor help like rust-analyzer, while ESLint plays a role similar to Clippy.
rust-analyzer is a language server that helps your editor understand Rust code. It provides features such as code completion, error messages, and “go to definition”. RustRover is an IDE made specifically for Rust.

For example, when you type `let message = String::from("Hello");`, rust-analyzer can suggest methods for `message` and show an error while you are still writing the code. Clippy can also point out code that could be clearer or more idiomatic.

#### Install bacon, cargo-nextest and cargo-expand
JavaScript comparison: file watchers, Jest or Vitest, and Babel's transformation output provide similar roles to Bacon, cargo-nextest, and cargo-expand.
bacon watches your Rust project and automatically runs checks when a file changes. cargo-nextest runs tests quickly and shows which tests pass or fail. cargo-expand shows the Rust code generated by macros.

For example, run `bacon clippy` to check your code continuously, `cargo nextest run` to run the test suite, or `cargo expand` to inspect what a macro generates.

#### `cargo new hello`, then `cd hello` and `cargo run`
JavaScript comparison: `npm run` needs a `package.json`, and Cargo needs a `Cargo.toml` in the same way. Cargo looks in the current folder and its parents, never in subfolders.
`cargo new hello && cargo run` created the project, but `cargo run` then ran in the folder above it and failed with "could not find `Cargo.toml`". Moving into the project first fixes it: `cd hello`, then `cargo run` builds `target/debug/hello` and prints `Hello, world!`.

#### `cargo clippy` is its own command
JavaScript comparison: `npm start` doesn't run ESLint; you run ESLint separately. `cargo run` doesn't run Clippy either.
Run `cargo clippy` inside the project. A clean result prints `Checking hello` and `Finished` with no `warning:` lines.

#### Clippy on save in VS Code
The setting is `"rust-analyzer.check.command": "clippy"` in VS Code's user settings. The older name, `rust-analyzer.checkOnSave.command`, is no longer read by current rust-analyzer, so it silently did nothing.
